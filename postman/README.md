# Перевірка API через Postman

Імпортуйте `paperbox.postman_collection.json` у Postman. Backend має працювати на порту 8000.

Змінна `base_url`: `http://127.0.0.1:8000/api/v1`.

## Вхід і перевірка прав

1. Виконайте `Список товарів` без токена. Очікується `200`, навіть якщо каталог порожній.
2. У папці `Автентифікація` виконайте `Реєстрація користувача` (`201`), потім `Вхід користувача` з тим самим іменем і паролем (`200`). Якщо користувач уже існує, достатньо виконати вхід.
3. У Postman відкрийте `Local Vault`. Із відповіді на вхід скопіюйте значення `access` у ключ `access_token`, а `refresh` у ключ `refresh_token`. Копіюйте лише значення, без лапок і без слова `Bearer`.
4. Виконайте `Мій профіль` - очікується `200` і дані користувача. Потім виконайте `Створення категорії` - очікується `403`, так як звичайний користувач не може змінювати каталог.
5. Виконайте `Оновлення токена доступу`. Очікується `200`. Нове значення `access` вручну запишіть у `access_token` у Local Vault, після чого повторіть `Мій профіль`.
6. Для перевірки змін каталогу потрібен адміністратор. Якщо його ще немає, у терміналі бекенду виконайте `python manage.py createsuperuser`. У запиті `Вхід адміна` вкажіть його `username`, а пароль збережіть у Local Vault під назвою `admin_password`.
7. Виконайте `Вхід адміна` та скопіюйте `access` із відповіді в окремий ключ `admin_access_token`. Запити для зміни каталогу використовують цей ключ. Якщо токен адміністратора прострочений, повторіть вхід адміністратора й оновіть `admin_access_token`.


## Порядок перевірки

1. Виконайте `admin_Створення категорії` та `Створення бренду`. Для кожного запиту очікується `201`. Запишіть ID із відповідей у змінні колекції `category_id` і `brand_id`.
2. Перевірте списки, перегляд і редагування категорії та бренду.
3. Після редагування виконайте запити з порожніми й повторними назвами, очікується 400.
4. Створіть товар і запишіть отриманий ID у `product_id`.
5. Перевірте список, перегляд, редагування товару, пошук, фільтрацію, сортування та першу сторінку.
6. Перевірте помилки даних товару й параметрів запиту. Очікується 400, а для неіснуючої сторінки 404.
7. Спробуйте видалити категорію та бренд із товаром, очікується 400.
8. Видаліть товар, потім категорію та бренд. Очікується 204 без тіла відповіді.
9. Перевірте перегляд видалених записів, очікується 404.

Запити виконуються вручну в цьому порядку. Автоматичний запуск усієї колекції через Run не налаштований.

Для повторної перевірки створіть записи заново та оновіть ID у змінних. Якщо попередня перевірка була перервана, видаліть залишені тестові записи. Спочатку товар, потім категорію та брендд. Інші записи каталогу залиште.

## Статуси відповідей

- 200 - успішне отримання або редагування.
- 201 - запис створено.
- 204 - запис видалено.
- 400 - некоректні дані або спроба видалити категорію чи бренд із товарами.
- 401 - неправильні дані для входу або відсутній, недійсний чи прострочений токен для захищеного запиту.
- 403 - користувач увійшов, але не має прав адміністратора для зміни каталогу.
- 404 - запис або сторінку не знайдено.

Помилки повертаються в об’єкті `error` з полями `message` та `details`.
